## 9.17. Sequence Manipulation Functions (sequence manipulation လုပ်ဆောင်ချက်များ)

ဒီ section က *sequence objects* (sequence generator များလို့လည်း ခေါ်ကြပြီး — ရိုးရိုး sequence လို့လည်း ခေါ်တတ်ပါတယ်) တွေကို လည်ပတ်ဖို့ (operate) function တွေကို ဖော်ပြပါတယ်။ Sequence objects တွေက [CREATE SEQUENCE](https://www.postgresql.org/docs/current/sql-createsequence.html) နဲ့ ဖန်တီးတဲ့ အထူး single-row table တွေ ဖြစ်ပါတယ်။ Table တစ်ခုရဲ့ rows တွေအတွက် ထူးခြားတဲ့ (unique) identifiers တွေ ထုတ်ပေးဖို့ sequence objects တွေကို အသုံးများပါတယ်။ အောက်ပါ ဇယား 9.55 မှာ စာရင်းပြုထားတဲ့ sequence functions တွေက — sequence objects တွေကနေ ဆက်တိုက် sequence တန်ဖိုးတွေ ရယူဖို့အတွက် — ရိုးရှင်းပြီး multiuser-safe (သုံးစွဲသူ အများအပြား အတွက် လုံခြုံသော) နည်းလမ်းတွေကို ပေးပါတယ်။

**ဇယား 9.55. Sequence Functions (sequence လုပ်ဆောင်ချက်များ)**

| Function ဖော်ပြချက် |
| --- |
| nextval ( regclass ) → bigint sequence object ကို ၎င်းရဲ့ နောက် တန်ဖိုးဆီ ရွေ့ပြီး ထိုတန်ဖိုးကို ပြန်ပေးပါတယ်။ ဒါကို atomic ဖြစ်အောင် လုပ်ဆောင်ပါတယ်: session အများအပြားက nextval ကို တစ်ပြိုင်တည်း (concurrently) execute လုပ်ကြရင်တောင် — session တစ်ခုချင်းစီဟာ ထူးခြားတဲ့ (distinct) sequence တန်ဖိုး တစ်ခုကို ဘေးကင်းစွာ ရရှိပါလိမ့်မယ်။ Sequence object ကို default parameters တွေနဲ့ ဖန်တီးထားရင် — ဆက်တိုက် nextval ခေါ်ဆိုမှုတွေက 1 ကနေ စပြီး ဆက်တိုက် တန်ဖိုးတွေကို ပြန်ပေးပါလိမ့်မယ်။ တခြား အပြုအမူတွေကိုတော့ CREATE SEQUENCE command မှာ သင့်လျော်တဲ့ parameters တွေကို သုံးခြင်းဖြင့် ရနိုင်ပါတယ်။ ဒီ function ကို သုံးဖို့ sequence ပေါ်မှာ USAGE သို့မဟုတ် UPDATE privilege လိုအပ်ပါတယ်။ |
| setval ( regclass, bigint [, boolean ] ) → bigint sequence object ရဲ့ လက်ရှိ တန်ဖိုးကို သတ်မှတ်ပေးပြီး — ရွေးချယ်နိုင်တဲ့ ၎င်းရဲ့ is_called flag ကိုလည်း သတ်မှတ်ပေးပါတယ်။ Argument နှစ်ခုပါတဲ့ ပုံစံ (two-parameter form) က sequence ရဲ့ last_value field ကို သတ်မှတ်ထားတဲ့ တန်ဖိုးအဖြစ် သတ်မှတ်ပြီး — ၎င်းရဲ့ is_called field ကို true အဖြစ် သတ်မှတ်ပါတယ်။ ဆိုလိုတာက နောက် nextval က တန်ဖိုး တစ်ခု ပြန်မပေးခင် sequence ကို ရှေ့ရွေ့ (advance) ပေးမှာ ဖြစ်ပါတယ်။ currval က ပြန်တင်ပြမယ့် တန်ဖိုးကိုလည်း သတ်မှတ်ထားတဲ့ တန်ဖိုးအဖြစ် သတ်မှတ်ပါတယ်။ Argument သုံးခုပါတဲ့ ပုံစံ (three-parameter form) မှာတော့ is_called ကို true သို့မဟုတ် false — တစ်ခုခုအဖြစ် သတ်မှတ်နိုင်ပါတယ်။ true က argument နှစ်ခုပါတဲ့ ပုံစံနဲ့ အတူတူပဲ ဖြစ်ပါတယ်။ false လို့ သတ်မှတ်ထားရင် — နောက် nextval က သတ်မှတ်ထားတဲ့ တန်ဖိုး အတိအကျကို ပြန်ပေးပြီး — sequence ရဲ့ ရှေ့ရွေ့မှု (advancement) က နောက်ဆက်တွဲ nextval ကစပြီး စတင်ပါတယ်။ ထို့ပြင် — ဒီကိစ္စမှာ currval က ပြန်တင်ပြတဲ့ တန်ဖိုးကို မပြောင်းလဲပါဘူး။ ဥပမာ — SELECT setval('myseq', 42); ကို ခေါ်ရင် နောက် nextval က 43 ကို ပြန်ပေးမယ်; SELECT setval('myseq', 42, true); ကို ခေါ်ရင် အထက်ပါအတိုင်း; SELECT setval('myseq', 42, false); ကို ခေါ်ရင် နောက် nextval က 42 ကို ပြန်ပေးမယ်။ setval က ပြန်ပေးတဲ့ ရလဒ်က ၎င်းရဲ့ ဒုတိယ argument ရဲ့ တန်ဖိုး သက်သက်ပဲ ဖြစ်ပါတယ်။ ဒီ function ကို သုံးဖို့ sequence ပေါ်မှာ UPDATE privilege လိုအပ်ပါတယ်။ |
| currval ( regclass ) → bigint လက်ရှိ session ထဲမှာ ဒီ sequence အတွက် nextval က နောက်ဆုံး ရယူခဲ့တဲ့ တန်ဖိုးကို ပြန်ပေးပါတယ်။ (ဒီ session ထဲမှာ ဒီ sequence အတွက် nextval ကို တစ်ခါမှ မခေါ်ရသေးရင် error တစ်ခု တင်ပြပါတယ်။) ဒါက session-local (session တစ်ခုအတွင်းသာ သက်ဆိုင်သော) တန်ဖိုး တစ်ခုကို ပြန်ပေးနေတာဖြစ်လို့ — လက်ရှိ session ပြီးနောက်ပိုင်း တခြား session တွေက nextval ကို execute လုပ်ခဲ့ကြလားဆိုတာ ဘယ်လိုပဲ ဖြစ်ဖြစ် — ကြိုတင် ခန့်မှန်းလို့ရတဲ့ (predictable) အဖြေ တစ်ခုကို ပေးပါတယ်။ ဒီ function ကို သုံးဖို့ sequence ပေါ်မှာ USAGE သို့မဟုတ် SELECT privilege လိုအပ်ပါတယ်။ |
| lastval () → bigint လက်ရှိ session ထဲမှာ nextval က နောက်ဆုံး ပြန်ပေးခဲ့တဲ့ တန်ဖိုးကို ပြန်ပေးပါတယ်။ ဒီ function က currval နဲ့ တူညီပါတယ် — ခြားနားချက်က sequence ရဲ့ နာမည်ကို argument အဖြစ် လက်ခံမယ့်အစား — လက်ရှိ session ထဲမှာ nextval ကို နောက်ဆုံး အသုံးပြုခဲ့တဲ့ sequence ကို ရည်ညွှန်းတာ ဖြစ်ပါတယ်။ လက်ရှိ session ထဲမှာ nextval ကို မခေါ်ရသေးဘဲ lastval ကို ခေါ်ရင် error တစ်ခု ဖြစ်ပါတယ်။ ဒီ function ကို သုံးဖို့ နောက်ဆုံး အသုံးပြုခဲ့တဲ့ sequence ပေါ်မှာ USAGE သို့မဟုတ် SELECT privilege လိုအပ်ပါတယ်။ |

> **သတိပြုရန်:** ဒီ sequence တစ်ခုတည်းကနေ နံပါတ်တွေ ရယူနေတဲ့ တစ်ပြိုင်နက် (concurrent) transaction တွေကို မပိတ်ဆို့မိစေဖို့အတွက် — `nextval` က ရယူလိုက်တဲ့ တန်ဖိုးကို — ခေါ်ဆိုတဲ့ transaction က နောက်မှ abort ဖြစ်သွားရင်တောင် — ပြန်လည် အသုံးပြုဖို့ (reclaim) ပြန်မသိမ်းပါဘူး။ ဆိုလိုတာက transaction abort တွေ သို့မဟုတ် database crash တွေကြောင့် — ခွဲဝေပေးလိုက်တဲ့ တန်ဖိုး အစဉ်အတန်းထဲမှာ gaps (ကွက်လပ်များ) ဖြစ်ပေါ်နိုင်ပါတယ်။ Transaction abort မရှိဘဲလည်း ဒါမျိုး ဖြစ်နိုင်ပါတယ်။ ဥပမာ — `ON CONFLICT` clause ပါတဲ့ `INSERT` တစ်ခုက — `ON CONFLICT` စည်းမျဉ်းကို လိုက်နာစေမယ့် conflict တစ်ခုကို မတွေ့ရှိရခင် — insert လုပ်မယ့် tuple ကို တွက်ချက်ရာမှာ လိုအပ်တဲ့ `nextval` ခေါ်ဆိုမှုတွေ အပါအဝင် လုပ်ဆောင်ပါလိမ့်မယ်။ ဒါကြောင့် — PostgreSQL ရဲ့ sequence objects တွေကို “gapless” (ကွက်လပ် ကင်းစင်သော) sequences တွေ ရယူဖို့ သုံးလို့ မရနိုင်ပါဘူး။
> 
> ထို့အတူ — `setval` က ပြုလုပ်တဲ့ sequence state အပြောင်းအလဲတွေက တခြား transaction တွေကို ချက်ချင်း မြင်နိုင်ပြီး — ခေါ်ဆိုတဲ့ transaction က roll back လုပ်လိုက်ရင်လည်း ပြန်ပြင် (undo) မပေးပါဘူး။
> 
> Database cluster က `nextval` သို့မဟုတ် `setval` ခေါ်ဆိုမှု ပါဝင်တဲ့ transaction တစ်ခု commit မဖြစ်ခင် crash ဖြစ်သွားရင် — sequence state ရဲ့ အပြောင်းအလဲဟာ persistent storage ဆီ မရောက်ရှိခဲ့လို့ — cluster ပြန်စတင်ပြီးနောက် sequence မှာ မူရင်း state ရှိမလား သို့မဟုတ် အပ်ဒိတ်လုပ်ထားတဲ့ state ရှိမလားဆိုတာ မသေချာနိုင်ပါဘူး။ ဒါက database အတွင်းမှာ sequence ကို အသုံးပြုခြင်းအတွက်တော့ အန္တရာယ် မရှိပါဘူး — အကြောင်းကတော့ commit မဖြစ်သေးတဲ့ transaction တွေရဲ့ တခြား သက်ရောက်မှုတွေလည်း မြင်ရမှာ မဟုတ်လို့ပါ။ ဒါပေမယ့် — database ပြင်ပက ရည်ရွယ်ချက်တွေအတွက် persistent (တည်မြဲသော) sequence တန်ဖိုး တစ်ခုကို သုံးချင်တယ်ဆိုရင် — အဲဒီလို မလုပ်ခင် `nextval` ခေါ်ဆိုမှုကို commit လုပ်ပြီးသား ဖြစ်အောင် သေချာစေပါ။

Sequence function တစ်ခုက လည်ပတ်စေမယ့် sequence ကို `regclass` argument တစ်ခုနဲ့ သတ်မှတ်ပါတယ် — ဒါက ရိုးရိုး `pg_class` system catalog ထဲက sequence ရဲ့ OID ပဲ ဖြစ်ပါတယ်။ ဒါပေမယ့် — `regclass` data type ရဲ့ input converter က အဲဒီအလုပ်ကို လုပ်ပေးမှာမို့ — OID ကို ကိုယ်တိုင် ရှာကြည့်စရာ မလိုပါဘူး။ အသေးစိတ်အတွက် [အပိုင်း 8.19](/docs/postgresql/datatype-oid) ကို ကြည့်ပါ။
