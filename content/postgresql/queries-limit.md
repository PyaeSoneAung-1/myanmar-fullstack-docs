## 7.6. `LIMIT` and `OFFSET` (LIMIT နှင့် OFFSET)

`LIMIT` နဲ့ `OFFSET` clause တွေက — query ရဲ့ ကျန်အပိုင်းတွေက ထုတ်လုပ်လိုက်တဲ့ row တွေထဲက အပိုင်းတစ်ပိုင်းကိုပဲ ပြန်လည် ရယူနိုင်အောင် ခွင့်ပြုပါတယ်:

```sql
SELECT select_list
    FROM table_expression
    [ ORDER BY ... ]
    [ LIMIT { count | ALL } ]
    [ OFFSET start ]
```

Limit count (ကန့်သတ်ထားတဲ့ row အရေအတွက်) ကို သတ်မှတ်ပေးထားရင် — ပြန်ပေးမယ့် row အရေအတွက်က အဲဒီထက် ပိုများမှာ မဟုတ်ပါဘူး (query ကိုယ်တိုင်က row နည်းနည်းပဲ ထုတ်ပေးနိုင်ရင်တော့ — ပိုနည်းတာလည်း ဖြစ်နိုင်ပါတယ်)။ `LIMIT ALL` က `LIMIT` clause ကို ချန်လိုက်တာနဲ့ အတူတူပဲ ဖြစ်ပြီး — NULL argument တစ်ခုပါတဲ့ `LIMIT` ကလည်း အတူတူပါပဲ။

`OFFSET` က — row တွေ စတင် ပြန်မပေးခင် — row အရေအတွက် ဘယ်လောက်ကို ကျော်သွားရမလဲဆိုတာကို သတ်မှတ်ပါတယ်။ `OFFSET 0` က `OFFSET` clause ကို ချန်လိုက်တာနဲ့ အတူတူပဲ ဖြစ်ပြီး — NULL argument တစ်ခုပါတဲ့ `OFFSET` ကလည်း အတူတူပါပဲ။

`OFFSET` ရော `LIMIT` ရော နှစ်ခုလုံး ပါဝင်နေရင် — ပြန်ပေးမယ့် `LIMIT` row တွေကို စတင် ရေတွက်ချိန်မှာ — `OFFSET` က သတ်မှတ်ထားတဲ့ row အရေအတွက်ကို အရင်ဆုံး ကျော်သွားပါတယ်။

`LIMIT` ကို သုံးတဲ့အခါ — result row တွေကို ထူးခြားတဲ့ (unique) အစဉ်တစ်ခုတည်းအတိုင်း ဖြစ်အောင် ကန့်သတ်ပေးတဲ့ `ORDER BY` clause တစ်ခုကို သုံးဖို့ အရေးကြီးပါတယ်။ မဟုတ်ရင် — query ရဲ့ row တွေထဲက ကြိုတင် ခန့်မှန်းလို့ မရတဲ့ (unpredictable) အစိတ်အပိုင်း တစ်ခုကို ရရှိမှာ ဖြစ်ပါတယ်။ ဥပမာ — ဆယ်ခုမြောက်ကနေ နှစ်ဆယ်ခုမြောက် row တွေကို သင်က တောင်းဆိုနေပေမယ့် — ဘယ်လို အစဉ်လိုက်ရှိတဲ့ ဆယ်ခုမြောက်ကနေ နှစ်ဆယ်ခုမြောက်လဲ? `ORDER BY` ကို သတ်မှတ်မထားဘူးဆိုရင် — အဲဒီအစဉ်ကို ဘယ်သူမှ မသိနိုင်ပါဘူး။

Query optimizer (query plan ရေးဆွဲပေးတဲ့ system အစိတ်အပိုင်း) က — query plan တွေ ထုတ်လုပ်တဲ့အခါ `LIMIT` ကိုပါ ထည့်သွင်း စဉ်းစားပါတယ် — ဒါကြောင့် — `LIMIT` နဲ့ `OFFSET` အတွက် သင်ပေးလိုက်တဲ့ တန်ဖိုးတွေပေါ် မူတည်ပြီး — (row အစဉ် မတူညီတဲ့) plan အမျိုးမျိုး ရရှိဖို့ အလားအလာ အလွန် များပါတယ်။ ဒါကြောင့် — query result ရဲ့ မတူညီတဲ့ အပိုင်းတွေကို ရွေးချယ်ဖို့ `LIMIT`/`OFFSET` တန်ဖိုး အမျိုးမျိုးကို သုံးမယ်ဆိုရင် — `ORDER BY` နဲ့ ကြိုတင် ခန့်မှန်းလို့ရတဲ့ result အစဉ်တစ်ခုကို အတင်းအကျပ် သတ်မှတ်မထားဘူးဆိုရင် — တစ်သမတ်တည်း မကျတဲ့ (inconsistent) ရလဒ်တွေ ရနိုင်ပါတယ်။ ဒါက bug မဟုတ်ပါဘူး — `ORDER BY` နဲ့ အစဉ်ကို ကန့်သတ်ထားခြင်း မရှိဘူးဆိုရင် — SQL က query တစ်ခုရဲ့ ရလဒ်တွေကို သီးခြား အစဉ်တစ်ခုခုနဲ့ ပို့ဆောင်ပေးမယ်လို့ ကတိမပေးဘူးဆိုတဲ့ အချက်ရဲ့ မွေးရာပါ အကျိုးဆက် (inherent consequence) တစ်ခုပဲ ဖြစ်လို့ပါ။

`OFFSET` clause က ကျော်သွားတဲ့ row တွေကိုတော့ — server အတွင်းမှာ တွက်ချက်နေရတုန်းပဲ ဖြစ်ပါတယ်; ဒါကြောင့် — `OFFSET` တန်ဖိုး ကြီးကြီးတစ်ခုက ထိရောက်မှု (efficiency) မရှိတဲ့ အခြေအနေ ဖြစ်စေနိုင်ပါတယ်။
