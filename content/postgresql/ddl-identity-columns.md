## 5.3. Identity Columns (sequence မှ တန်ဖိုး အလိုအလျောက် ထုတ်ပေးသော column များ)

Identity column ဆိုတာ — implicit sequence (နောက်ကွယ်မှာ အလိုအလျောက် ဖန်တီးပေးတဲ့ sequence) တစ်ခုကနေ အလိုအလျောက် ထုတ်ပေးတဲ့ အထူး column တစ်မျိုး ဖြစ်ပါတယ်။ Key value တွေ ထုတ်ပေးဖို့ သုံးနိုင်ပါတယ်။

Identity column တစ်ခု ဖန်တီးဖို့ — `CREATE TABLE` ထဲမှာ `GENERATED ... AS IDENTITY` clause ကို သုံးပါတယ်။ ဥပမာ:

```sql
CREATE TABLE people (
    id bigint GENERATED ALWAYS AS IDENTITY,
    ...,
);
```

ဒါမှမဟုတ် — တနည်းအားဖြင့်:

```sql
CREATE TABLE people (
    id bigint GENERATED BY DEFAULT AS IDENTITY,
    ...,
);
```

အသေးစိတ်ကို [CREATE TABLE](https://www.postgresql.org/docs/current/sql-createtable.html) မှာ ကြည့်ပါ။

Identity column ပါတဲ့ table ပေါ်မှာ `INSERT` command တစ်ခု run လုပ်ပြီး — identity column အတွက် တန်ဖိုးကို အတိအကျ သတ်မှတ်မပေးရင် — implicit sequence က ထုတ်ပေးတဲ့ တန်ဖိုး တစ်ခုကို insert လုပ်ပါတယ်။ ဥပမာ — အပေါ်က definitions တွေနဲ့အတူ — သင့်လျော်တဲ့ column တွေ ထပ်ရှိတယ်လို့ ယူဆပြီး အောက်ပါအတိုင်း ရေးလိုက်ရင်:

```sql
INSERT INTO people (name, address) VALUES ('A', 'foo');
INSERT INTO people (name, address) VALUES ('B', 'bar');
```

`id` column အတွက် တန်ဖိုးတွေကို 1 ကနေ စတင်ပြီး ထုတ်ပေးမှာ ဖြစ်လို့ — အောက်ပါ table data တွေ ရလာပါလိမ့်မယ်:

```sql
 id | name | address
----+------+---------
  1 | A    | foo
  2 | B    | bar
```

တနည်းအားဖြင့် — sequence ကနေ ထုတ်ပေးတဲ့ တန်ဖိုးကို အတိအကျ တောင်းဆိုချင်ရင် တန်ဖိုး နေရာမှာ `DEFAULT` keyword ကို သုံးနိုင်ပါတယ် — ဥပမာ:

```sql
INSERT INTO people (id, name, address) VALUES (DEFAULT, 'C', 'baz');
```

အလားတူပဲ — `UPDATE` command တွေမှာလည်း `DEFAULT` keyword ကို သုံးနိုင်ပါတယ်။

ဒါကြောင့် — နည်းများစွာနဲ့ ကြည့်ရင် identity column က default value ရှိတဲ့ column တစ်ခုလို ပြုမူပါတယ်။

Column definition ထဲက `ALWAYS` နဲ့ `BY DEFAULT` clause တွေက — `INSERT` နဲ့ `UPDATE` command တွေမှာ user က အတိအကျ သတ်မှတ်ပေးတဲ့ တန်ဖိုးတွေကို ဘယ်လို ကိုင်တွယ်မလဲဆိုတာ ဆုံးဖြတ်ပါတယ်။ `INSERT` command တစ်ခုမှာ `ALWAYS` ရွေးထားရင် — user သတ်မှတ်တဲ့ တန်ဖိုးကို `INSERT` statement က `OVERRIDING SYSTEM VALUE` လို့ သတ်မှတ်ထားမှသာ လက်ခံပါတယ်။ `BY DEFAULT` ရွေးထားရင် — user သတ်မှတ်တဲ့ တန်ဖိုးက ဦးစားပေး ဖြစ်ပါတယ်။ ဒါကြောင့် `BY DEFAULT` သုံးခြင်းက — အတိအကျ တန်ဖိုး တစ်ခုနဲ့ override (အစားထိုး) လို့ရတဲ့ default value တွေနဲ့ ပိုတူတဲ့ အပြုအမူကို ရစေပြီး — `ALWAYS` ကတော့ explicit value တစ်ခုကို မတော်တဆ ထည့်မိတာကနေ ပိုပြီး ကာကွယ်ပေးပါတယ်။

Identity column ရဲ့ data type က — sequence တွေ ထောက်ပံ့ပေးတဲ့ data type တွေထဲက တစ်ခု ဖြစ်ရပါမယ်။ ([CREATE SEQUENCE](https://www.postgresql.org/docs/current/sql-createsequence.html) ကို ကြည့်ပါ။) ဆက်စပ်နေတဲ့ sequence ရဲ့ properties တွေကို — identity column ဖန်တီးတဲ့အခါ သတ်မှတ်နိုင်ပါတယ် ([CREATE TABLE](https://www.postgresql.org/docs/current/sql-createtable.html) ကို ကြည့်ပါ) — ဒါမှမဟုတ် နောက်မှ ပြောင်းလဲလို့လည်း ရပါတယ် ([ALTER TABLE](https://www.postgresql.org/docs/current/sql-altertable.html) ကို ကြည့်ပါ)။

Identity column တစ်ခုကို `NOT NULL` အဖြစ် အလိုအလျောက် မှတ်သားပါတယ်။ ဒါပေမယ့် — identity column က uniqueness (တန်ဖိုး ထပ်မဖြစ်ခြင်း) ကို အာမခံပါဘူး။ (Sequence က ပုံမှန်အားဖြင့် unique တန်ဖိုးတွေ ပြန်ပေးပါတယ် — ဒါပေမယ့် sequence ကို reset လုပ်လို့ရသလို — အပေါ်မှာ ဆွေးနွေးခဲ့သလို — identity column ထဲကို လက်နဲ့ တန်ဖိုး ထည့်လို့လည်း ရပါတယ်။) Uniqueness ကိုတော့ `PRIMARY KEY` ဒါမှမဟုတ် `UNIQUE` constraint တစ်ခုနဲ့ သေချာ ပြဋ္ဌာန်းပေးဖို့ လိုပါတယ်။

Table inheritance အဆင့်ဆင့် (hierarchy) တွေထဲမှာ — child table ထဲက identity column တွေနဲ့ သူတို့ရဲ့ properties တွေက parent table တွေထဲကဟာတွေနဲ့ သီးခြားစီ ဖြစ်ပါတယ်။ Child table က identity column တွေကို (ဒါမှမဟုတ် သူတို့ရဲ့ properties တွေကို) parent ဆီကနေ အလိုအလျောက် အမွေမရပါဘူး။ `INSERT` ဒါမှမဟုတ် `UPDATE` လုပ်ဆောင်တဲ့အခါ — statement ထဲမှာ ဖော်ပြထားတဲ့ table ရဲ့ column တစ်ခုက identity column ဖြစ်နေရင် — အဲဒီ column ကို identity column အဖြစ် သဘောထားပြီး — သက်ဆိုင်တဲ့ identity properties တွေကို အသုံးပြုပါတယ်။

Partition တွေက partitioned table ဆီကနေ identity column တွေကို အမွေရပါတယ်။ သူတို့မှာ ကိုယ်ပိုင် identity column တွေ ထားလို့ မရပါဘူး။ Identity column တစ်ခုရဲ့ properties တွေက partition hierarchy (partition အဆင့်ဆင့်) တစ်ခုလုံးမှာ တစ်သမတ်တည်း ဖြစ်နေပါတယ်။
