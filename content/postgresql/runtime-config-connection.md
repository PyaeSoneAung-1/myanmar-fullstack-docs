## 19.3. Connections and Authentication (ချိတ်ဆက်မှုနှင့် authentication)

### 19.3.1. Connection Settings (ချိတ်ဆက်မှု setting များ)

- **listen_addresses (string)** — Server က client application များထံမှ ချိတ်ဆက်မှုများအတွက် နားထောင် (listen) မည့် TCP/IP address(များ) ကို သတ်မှတ်ပါတယ်။ တန်ဖိုးက host name များနှင့်/သို့မဟုတ် ကိန်းဂဏန်း IP address များကို comma နဲ့ ခွဲထားတဲ့ စာရင်း ပုံစံ ဖြစ်ပါတယ်။ အထူး entry ဖြစ်တဲ့ * က ရရှိနိုင်တဲ့ IP interface အားလုံးနှင့် သက်ဆိုင်ပါတယ်။ Entry 0.0.0.0 က IPv4 address အားလုံးအတွက် နားထောင်ခွင့်ပြုပြီး :: က IPv6 address အားလုံးအတွက် နားထောင်ခွင့်ပြုပါတယ်။ စာရင်းက ဗလာ ဖြစ်ရင် server က IP interface တစ်ခုမှာ လုံးဝ နားထောင်မှာ မဟုတ်ဘဲ — ဒီအခြေအနေမှာ Unix-domain socket များဖြင့်သာ ချိတ်ဆက်နိုင်ပါတယ်။ စာရင်းက ဗလာ မဟုတ်ရင် — server က အနည်းဆုံး TCP/IP address တစ်ခုမှာ နားထောင်နိုင်ရင် စတင် (start) ပါလိမ့်မယ်။ ဖွင့်လို့ မရတဲ့ TCP/IP address တစ်ခုချင်းစီအတွက် warning တစ်ခု ထုတ်ပြပါလိမ့်မယ်။ ပုံမှန် (default) တန်ဖိုးက localhost ဖြစ်ပြီး — ဒါက local TCP/IP “loopback” ချိတ်ဆက်မှုများကိုသာ ပြုလုပ်ခွင့်ပြုပါတယ်။
  Client authentication ([အခန်း 20](https://www.postgresql.org/docs/current/client-authentication.html)) က server ကို မည်သူ ဝင်ရောက်နိုင်သည် ဆိုတာကို သေသပ်စွာ ထိန်းချုပ်ခွင့်ပြုပေမယ့် — listen_addresses က ဘယ် interface များက ချိတ်ဆက်ရန် တောင်းဆိုမှုများကို လက်ခံမည်ကို ထိန်းချုပ်ပြီး — ဒါက လုံခြုံမှုမရှိတဲ့ network interface များပေါ်မှာ ထပ်ခါတလဲလဲ ဖြစ်ပေါ်တဲ့ မလိုလားအပ်တဲ့ ချိတ်ဆက်ရန် တောင်းဆိုမှုများကို တားဆီးရန် အထောက်အကူ ဖြစ်နိုင်ပါတယ်။ ဒီ parameter ကို server စတင်ချိန်မှာသာ သတ်မှတ်နိုင်ပါတယ်။
- **port (integer)** — Server နားထောင်တဲ့ TCP port ဖြစ်ပြီး — ပုံမှန်အားဖြင့် 5432 ဖြစ်ပါတယ်။ Server နားထောင်တဲ့ IP address အားလုံးအတွက် port နံပါတ် တူညီတာကို သုံးတယ်ဆိုတာ သတိပြုပါ။ ဒီ parameter ကို server စတင်ချိန်မှာသာ သတ်မှတ်နိုင်ပါတယ်။
- **max_connections (integer)** — Database server သို့ တစ်ပြိုင်နက်တည်း (concurrent) ချိတ်ဆက်မှု အများဆုံး အရေအတွက်ကို ဆုံးဖြတ်ပါတယ်။ ပုံမှန်အားဖြင့် connection 100 ခုခန့် ဖြစ်ပြီး — kernel setting များက မထောက်ပံ့နိုင်ရင် (initdb လုပ်ချိန်မှာ ဆုံးဖြတ်သည့်အတိုင်း) ပိုနည်းနိုင်ပါတယ်။ ဒီ parameter ကို server စတင်ချိန်မှာသာ သတ်မှတ်နိုင်ပါတယ်။
  PostgreSQL က အချို့ resource များကို max_connections ရဲ့ တန်ဖိုးပေါ် တိုက်ရိုက် အခြေခံပြီး အရွယ်အစား သတ်မှတ်ပါတယ်။ သူ့တန်ဖိုး တိုးမြှင့်ခြင်းက shared memory အပါအဝင် အဲဒီ resource များကို ပိုမို ခွဲဝေပေးမှု (allocation) ဖြစ်စေပါတယ်။
  Standby server ကို run လုပ်တဲ့အခါ ဒီ parameter ကို primary server ပေါ်က တန်ဖိုးနဲ့ တူညီ ဒါမှမဟုတ် ပိုမြင့်တဲ့ တန်ဖိုး သတ်မှတ်ရပါမယ်။ မဟုတ်ရင် standby server မှာ query များကို ခွင့်ပြုမှာ မဟုတ်ပါဘူး။
- **reserved_connections (integer)** — [pg_use_reserved_connections](/docs/postgresql/predefined-roles) role ရဲ့ privilege များ ရှိတဲ့ role များမှ ချိတ်ဆက်မှုများအတွက် သီးသန့်ထားတဲ့ connection “slot” အရေအတွက်ကို ဆုံးဖြတ်ပါတယ်။ လွတ်နေတဲ့ connection slot အရေအတွက်က superuser_reserved_connections ထက် ပိုပြီး — superuser_reserved_connections နဲ့ reserved_connections ရဲ့ ပေါင်းလဒ်ထက် မပိုတဲ့အခါ — connection အသစ်များကို superuser များနဲ့ pg_use_reserved_connections ရဲ့ privilege များ ရှိတဲ့ role များအတွက်သာ လက်ခံပါလိမ့်မယ်။ superuser_reserved_connections သို့မဟုတ် ထိုထက်နည်းတဲ့ connection slot များ ရရှိနိုင်ရင် connection အသစ်များကို superuser များအတွက်သာ လက်ခံပါလိမ့်မယ်။
  ပုံမှန် တန်ဖိုးက connection သုည ဖြစ်ပါတယ်။ တန်ဖိုးက max_connections မှ superuser_reserved_connections ကို နုတ်တာထက် နည်းရပါမယ်။ ဒီ parameter ကို server စတင်ချိန်မှာသာ သတ်မှတ်နိုင်ပါတယ်။
- **superuser_reserved_connections (integer)** — PostgreSQL superuser များ၏ ချိတ်ဆက်မှုများအတွက် သီးသန့်ထားတဲ့ connection “slot” အရေအတွက်ကို ဆုံးဖြတ်ပါတယ်။ အများဆုံး max_connections connection များသာ တစ်ပြိုင်နက်တည်း active ဖြစ်နိုင်ပါတယ်။ Active concurrent connection အရေအတွက်က အနည်းဆုံး max_connections မှ superuser_reserved_connections ကို နုတ်တာ ရှိတဲ့အခါ connection အသစ်များကို superuser များအတွက်သာ လက်ခံပါလိမ့်မယ်။ ဒီ parameter က သီးသန့်ထားတဲ့ connection slot များက reserved_connections က သီးသန့်ထားတဲ့ slot များ ကုန်ဆုံးသွားပြီးနောက် အရေးပေါ် အသုံးပြုရန် နောက်ဆုံး အရန် (final reserve) အဖြစ် ရည်ရွယ်ထားပါတယ်။
  ပုံမှန် တန်ဖိုးက connection သုံးခု ဖြစ်ပါတယ်။ တန်ဖိုးက max_connections မှ reserved_connections ကို နုတ်တာထက် နည်းရပါမယ်။ ဒီ parameter ကို server စတင်ချိန်မှာသာ သတ်မှတ်နိုင်ပါတယ်။
- **unix_socket_directories (string)** — Server က client application များထံမှ ချိတ်ဆက်မှုများအတွက် နားထောင်မည့် Unix-domain socket(များ) ရဲ့ directory ကို သတ်မှတ်ပါတယ်။ Directory များကို comma နဲ့ ခွဲပြီး စာရင်းပြခြင်းဖြင့် socket များစွာ ဖန်တီးနိုင်ပါတယ်။ Entry များကြားက whitespace ကို လျစ်လျူရှုပါတယ်; Directory name ထဲမှာ whitespace ဒါမှမဟုတ် comma ထည့်ရန် လိုအပ်ရင် directory name ကို double quote နဲ့ ခြုံပါ။ ဗလာ တန်ဖိုးက Unix-domain socket များတွင် နားထောင်ခြင်း မရှိကြောင်း သတ်မှတ်ပြီး — အဲဒီအခါ TCP/IP socket များဖြင့်သာ server ကို ချိတ်ဆက်နိုင်ပါတယ်။
  @ နဲ့ စတဲ့ တန်ဖိုးက abstract namespace ထဲက Unix-domain socket တစ်ခု ဖန်တီးသင့်ကြောင်း သတ်မှတ်ပါတယ် (လောလောဆယ် Linux မှာသာ ပံ့ပိုးသည်)။ အဲဒီအခါ ဒီတန်ဖိုးက “directory” ကို သတ်မှတ်တာ မဟုတ်ဘဲ — file-system namespace အတွက်ကဲ့သို့ပဲ socket name အမှန်တကယ်ကို တွက်ချက်ရာ prefix တစ်ခုကို သတ်မှတ်တာပါ။ Abstract socket name prefix ကို လွတ်လပ်စွာ ရွေးချယ်နိုင်ပေမယ့် — ဒါက file-system တည်နေရာ မဟုတ်တာကြောင့် — များသောအားဖြင့် @/tmp ကဲ့သို့ file-system နဲ့ တူတဲ့ တန်ဖိုးများကို သုံးလေ့ရှိပါတယ်။
  ပုံမှန် တန်ဖိုးက ပုံမှန်အားဖြင့် /tmp ဖြစ်ပြီး — ဒါကို build ချိန်မှာ ပြောင်းလဲနိုင်ပါတယ်။ Windows မှာတော့ ပုံမှန်တန်ဖိုးက ဗလာ ဖြစ်ပြီး — ဆိုလိုတာက ပုံမှန်အားဖြင့် Unix-domain socket ဖန်တီးမှာ မဟုတ်ပါဘူး။ ဒီ parameter ကို server စတင်ချိန်မှာသာ သတ်မှတ်နိုင်ပါတယ်။
  Socket file ကိုယ်တိုင် (.s.PGSQL.nnnn လို့ အမည်ရပြီး nnnn က server ရဲ့ port နံပါတ် ဖြစ်သည်) အပြင် — .s.PGSQL.nnnn.lock လို့ အမည်ရတဲ့ သာမန် file တစ်ခုကို unix_socket_directories directory တစ်ခုချင်းစီမှာ ဖန်တီးပါလိမ့်မယ်။ File နှစ်ခုလုံးကို လက်ဖြင့် ဖျက်သင့်တာ မရှိပါဘူး။ Abstract namespace ထဲက socket များအတွက်တော့ lock file ဖန်တီးမှာ မဟုတ်ပါဘူး။
- **unix_socket_group (string)** — Unix-domain socket(များ) ရဲ့ ပိုင်ဆိုင်တဲ့ group ကို သတ်မှတ်ပါတယ်။ (Socket များရဲ့ ပိုင်ဆိုင်တဲ့ user က server ကို စတင်တဲ့ user အမြဲ ဖြစ်သည်။) unix_socket_permissions parameter နဲ့ ပေါင်းစပ်ပြီး — Unix-domain ချိတ်ဆက်မှုများအတွက် အပို access control ယန္တရား အဖြစ် သုံးနိုင်ပါတယ်။ ပုံမှန်အားဖြင့် ဒါက ဗလာ string ဖြစ်ပြီး — ဆိုလိုတာက server user ရဲ့ ပုံမှန် group ကို သုံးတာပါ။ ဒီ parameter ကို server စတင်ချိန်မှာသာ သတ်မှတ်နိုင်ပါတယ်။
  ဒီ parameter ကို Windows မှာ ပံ့ပိုးမထားပါဘူး။ မည်သည့် setting မဆို လျစ်လျူရှုခံရမှာ ဖြစ်ပါတယ်။ ဒါ့အပြင် abstract namespace ထဲက socket များမှာ file ပိုင်ရှင် မရှိတာကြောင့် — အဲဒီအခြေအနေမှာလည်း ဒီ setting ကို လျစ်လျူရှုပါတယ်။
- **unix_socket_permissions (integer)** — Unix-domain socket(များ) ရဲ့ access permission များကို သတ်မှတ်ပါတယ်။ Unix-domain socket များက ပုံမှန် Unix file system permission set ကို သုံးပါတယ်။ Parameter တန်ဖိုးက chmod နဲ့ umask system call များ လက်ခံတဲ့ format နဲ့ သတ်မှတ်ထားတဲ့ numeric mode တစ်ခု ဖြစ်ရန် မျှော်လင့်ပါတယ်။ (ထုံးစံအတိုင်း octal format သုံးရန် နံပါတ်က 0 (သုည) နဲ့ စရပါမယ်။)
  ပုံမှန် permission များက 0777 ဖြစ်ပြီး — ဆိုလိုတာက မည်သူမဆို ချိတ်ဆက်နိုင်တာပါ။ သင့်တင့်တဲ့ အခြား ရွေးချယ်မှုများက 0770 (user နဲ့ group သာ၊ unix_socket_group ကိုလည်း ကြည့်ပါ) နဲ့ 0700 (user သာ) ဖြစ်ပါတယ်။ (Unix-domain socket တစ်ခုအတွက် write permission သာ အရေးပါတာကြောင့် — read ဒါမှမဟုတ် execute permission များကို သတ်မှတ်ခြင်း ဒါမှမဟုတ် ရုပ်သိမ်းခြင်းမှာ အကျိုးမရှိပါဘူး။)
  ဒီ access control ယန္တရားက [အခန်း 20](https://www.postgresql.org/docs/current/client-authentication.html) မှာ ဖော်ပြထားတဲ့ ယန္တရားနဲ့ သီးခြား ဖြစ်ပါတယ်။
  ဒီ parameter ကို server စတင်ချိန်မှာသာ သတ်မှတ်နိုင်ပါတယ်။
  ဒီ parameter က socket permission များကို လုံးဝ လျစ်လျူရှုတဲ့ system များ — အထူးသဖြင့် Solaris 10 ကတည်းက Solaris — အတွက် အရေးမပါပါဘူး။ အဲဒီမှာ — လိုချင်တဲ့ ပရိသတ်အတွက်သာ search permission ကန့်သတ်ထားတဲ့ directory တစ်ခုဆီ unix_socket_directories ကို ညွှန်ပြခြင်းဖြင့် အလားတူ အကျိုးသက်ရောက်မှုကို ရရှိနိုင်ပါတယ်။
  Abstract namespace ထဲက socket များမှာ file permission များ မရှိတာကြောင့် — အဲဒီအခြေအနေမှာလည်း ဒီ setting ကို လျစ်လျူရှုပါတယ်။
- **bonjour (boolean)** — Bonjour မှတစ်ဆင့် server ရှိနေကြောင်း ကြေညာခြင်း (advertise) ကို ဖွင့်ပေးပါတယ်။ ပုံမှန်က off ဖြစ်ပါတယ်။ ဒီ parameter ကို server စတင်ချိန်မှာသာ သတ်မှတ်နိုင်ပါတယ်။
- **bonjour_name (string)** — Bonjour service name ကို သတ်မှတ်ပါတယ်။ ဒီ parameter ကို ဗလာ string '' (ဒါက ပုံမှန်) သတ်မှတ်ရင် computer name ကို သုံးပါတယ်။ Server ကို Bonjour support နဲ့ compile မလုပ်ထားရင် ဒီ parameter ကို လျစ်လျူရှုပါတယ်။ ဒီ parameter ကို server စတင်ချိန်မှာသာ သတ်မှတ်နိုင်ပါတယ်။

### 19.3.2. TCP Settings (TCP setting များ)

- **tcp_keepalives_idle (integer)** — Network လှုပ်ရှားမှု မရှိဘဲ ကြာချိန် ဘယ်လောက် ကြာပြီးနောက် operating system က client ဆီ TCP keepalive message ပို့သင့်သည်ကို သတ်မှတ်ပါတယ်။ ဒီတန်ဖိုးကို unit မပါဘဲ သတ်မှတ်ရင် စက္ကန့်အဖြစ် ယူပါတယ်။ တန်ဖိုး 0 (ပုံမှန်) က operating system ရဲ့ ပုံမှန်တန်ဖိုးကို ရွေးပါတယ်။ Windows မှာ — Windows က system default တန်ဖိုးကို ဖတ်ရန် နည်းလမ်း မပေးတာကြောင့် — တန်ဖိုး 0 သတ်မှတ်ခြင်းက ဒီ parameter ကို 2 နာရီ ဖြစ်စေပါတယ်။ ဒီ parameter ကို TCP_KEEPIDLE ဒါမှမဟုတ် သူနဲ့ ထူးတူတဲ့ socket option ကို ပံ့ပိုးတဲ့ system များနဲ့ Windows မှာသာ ပံ့ပိုးပါတယ်; အခြား system များမှာတော့ သုည ဖြစ်ရပါမယ်။ Unix-domain socket မှတစ်ဆင့် ချိတ်ဆက်ထားတဲ့ session များမှာ ဒီ parameter ကို လျစ်လျူရှုပြီး အမြဲ သုည အဖြစ်သာ ဖတ်ပါတယ်။
- **tcp_keepalives_interval (integer)** — Client က အတည်ပြုမထားတဲ့ (acknowledged မလုပ်ရသေးတဲ့) TCP keepalive message ကို ပြန်ပို့ (retransmit) သင့်သည့် ကြာချိန်ကို သတ်မှတ်ပါတယ်။ ဒီတန်ဖိုးကို unit မပါဘဲ သတ်မှတ်ရင် စက္ကန့်အဖြစ် ယူပါတယ်။ တန်ဖိုး 0 (ပုံမှန်) က operating system ရဲ့ ပုံမှန်တန်ဖိုးကို ရွေးပါတယ်။ Windows မှာ — Windows က system default တန်ဖိုးကို ဖတ်ရန် နည်းလမ်း မပေးတာကြောင့် — တန်ဖိုး 0 သတ်မှတ်ခြင်းက ဒီ parameter ကို 1 စက္ကန့် ဖြစ်စေပါတယ်။ ဒီ parameter ကို TCP_KEEPINTVL ဒါမှမဟုတ် သူနဲ့ ထူးတူတဲ့ socket option ကို ပံ့ပိုးတဲ့ system များနဲ့ Windows မှာသာ ပံ့ပိုးပါတယ်; အခြား system များမှာတော့ သုည ဖြစ်ရပါမယ်။ Unix-domain socket မှတစ်ဆင့် ချိတ်ဆက်ထားတဲ့ session များမှာ ဒီ parameter ကို လျစ်လျူရှုပြီး အမြဲ သုည အဖြစ်သာ ဖတ်ပါတယ်။
- **tcp_keepalives_count (integer)** — Server ရဲ့ client ဆီ ချိတ်ဆက်မှုကို သေသွားပြီ (dead) လို့ သတ်မှတ်ခင် ဆုံးရှုံးနိုင်တဲ့ TCP keepalive message အရေအတွက်ကို သတ်မှတ်ပါတယ်။ တန်ဖိုး 0 (ပုံမှန်) က operating system ရဲ့ ပုံမှန်တန်ဖိုးကို ရွေးပါတယ်။ ဒီ parameter ကို TCP_KEEPCNT ဒါမှမဟုတ် သူနဲ့ ထူးတူတဲ့ socket option ကို ပံ့ပိုးတဲ့ system များမှာသာ ပံ့ပိုးပါတယ် (Windows မပါဝင်ပါ); အခြား system များမှာတော့ သုည ဖြစ်ရပါမယ်။ Unix-domain socket မှတစ်ဆင့် ချိတ်ဆက်ထားတဲ့ session များမှာ ဒီ parameter ကို လျစ်လျူရှုပြီး အမြဲ သုည အဖြစ်သာ ဖတ်ပါတယ်။
- **tcp_user_timeout (integer)** — TCP ချိတ်ဆက်မှုကို အတင်းအကျပ် ပိတ်ခင် ပို့ထားတဲ့ data က အတည်ပြုမခံရဘဲ (unacknowledged) ကျန်နိုင်တဲ့ ကြာချိန်ကို သတ်မှတ်ပါတယ်။ ဒီတန်ဖိုးကို unit မပါဘဲ သတ်မှတ်ရင် မီလီစက္ကန့်အဖြစ် ယူပါတယ်။ တန်ဖိုး 0 (ပုံမှန်) က operating system ရဲ့ ပုံမှန်တန်ဖိုးကို ရွေးပါတယ်။ ဒီ parameter ကို TCP_USER_TIMEOUT ကို ပံ့ပိုးတဲ့ system များမှာသာ ပံ့ပိုးပါတယ် (Windows မပါဝင်ပါ); အခြား system များမှာတော့ သုည ဖြစ်ရပါမယ်။ Unix-domain socket မှတစ်ဆင့် ချိတ်ဆက်ထားတဲ့ session များမှာ ဒီ parameter ကို လျစ်လျူရှုပြီး အမြဲ သုည အဖြစ်သာ ဖတ်ပါတယ်။
- **client_connection_check_interval (integer)** — Query များ run နေစဉ် client က ချိတ်ဆက်ထားဆဲ ဖြစ်ကြောင်း ရွေးချယ်စစ်ဆေးမှုများ (optional check) အကြား အချိန် interval ကို သတ်မှတ်ပါတယ်။ စစ်ဆေးမှုကို socket ကို poll လုပ်ခြင်းဖြင့် ပြုလုပ်ပြီး — kernel က ချိတ်ဆက်မှု ပိတ်သွားကြောင်း အစီရင်ခံတဲ့အခါ — ကြာချိန်ရှည်တဲ့ query များကို စောစောပိုင်း ရပ်ဆိုင်းခွင့်ပြုပါတယ်။
  ဒီ option က Linux, macOS, illumos နဲ့ BSD မျိုးရင်း operating system များ ဖော်ထုတ်တဲ့ kernel event များပေါ် မှီခိုပြီး — လောလောဆယ် အခြား system များမှာ မရရှိနိုင်ပါဘူး။
  တန်ဖိုးကို unit မပါဘဲ သတ်မှတ်ရင် မီလီစက္ကန့်အဖြစ် ယူပါတယ်။ ပုံမှန် တန်ဖိုးက 0 ဖြစ်ပြီး — ဒါက ချိတ်ဆက်မှု စစ်ဆေးခြင်းကို ပိတ်ပါတယ်။ ချိတ်ဆက်မှု စစ်ဆေးခြင်း မရှိဘဲ — server က ချိတ်ဆက်မှု ဆုံးရှုံးတာကို socket နဲ့ နောက်တစ်ကြိမ် ဆက်သွယ်ချိန် — ဆိုလိုတာက data ကို စောင့်ဆိုင်း၊ လက်ခံ ဒါမှမဟုတ် ပို့ချိန် — မှသာ သိရှိပါလိမ့်မယ်။
  Network ပျက်ကွက်မှု အပါအဝင် အခြေအနေ အားလုံးမှာ kernel ကိုယ်တိုင် ဆုံးရှုံးသွားတဲ့ TCP ချိတ်ဆက်မှုများကို စိတ်ချရပြီး သိသာတဲ့ အချိန်အတွင်း ရှာဖွေနိုင်ရန် — operating system ရဲ့ TCP keepalive setting များ ဒါမှမဟုတ် PostgreSQL ရဲ့ tcp_keepalives_idle, tcp_keepalives_interval နဲ့ tcp_keepalives_count setting များကို ချိန်ညှိရန် လိုအပ်နိုင်ပါတယ်။

### 19.3.3. Authentication (authentication စစ်ဆေး အတည်ပြုခြင်း)

- **authentication_timeout (integer)** — Client authentication ကို ပြီးမြောက်စေရန် ခွင့်ပြုတဲ့ အများဆုံး ကြာချိန်။ Client လောင်းလျာတစ်ဦးက ဒီကြာချိန်အတွင်း authentication protocol ကို ပြီးမြောက်အောင် မလုပ်နိုင်ရင် server က ချိတ်ဆက်မှုကို ပိတ်ပါတယ်။ ဒါက ပိတ်မိနေတဲ့ (hung) client များက connection တစ်ခုကို အကန့်အသတ်မရှိ သိမ်းပိုက်ထားတာကို တားဆီးပါတယ်။ ဒီတန်ဖိုးကို unit မပါဘဲ သတ်မှတ်ရင် စက္ကန့်အဖြစ် ယူပါတယ်။ ပုံမှန်က တစ်မိနစ် (1m) ဖြစ်ပါတယ်။ ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။
- **password_encryption (enum)** — [CREATE ROLE](/docs/postgresql/sql-createrole) ဒါမှမဟုတ် [ALTER ROLE](/docs/postgresql/sql-alterrole) မှာ စကားဝှက် သတ်မှတ်တဲ့အခါ ဒီ parameter က စကားဝှက်ကို encrypt လုပ်ရန် သုံးမည့် algorithm ကို ဆုံးဖြတ်ပါတယ်။ ဖြစ်နိုင်တဲ့ တန်ဖိုးများက — စကားဝှက်ကို SCRAM-SHA-256 နဲ့ encrypt လုပ်မည့် scram-sha-256 နဲ့ — စကားဝှက်ကို MD5 hash အဖြစ် သိမ်းဆည်းမည့် md5 ဖြစ်ပါတယ်။ ပုံမှန်က scram-sha-256 ဖြစ်ပါတယ်။
  Client အဟောင်းများက SCRAM authentication ယန္တရားကို ပံ့ပိုးမှု မရှိနိုင်ပြီး — ထို့ကြောင့် SCRAM-SHA-256 နဲ့ encrypt လုပ်ထားတဲ့ စကားဝှက်များနဲ့ အလုပ်မလုပ်နိုင်ပါဘူး။ အသေးစိတ်အတွက် [အပိုင်း 20.5](/docs/postgresql/auth-password) ကို ကြည့်ပါ။

> **သတိပေးချက်:** MD5 နဲ့ encrypt လုပ်ထားတဲ့ စကားဝှက်များအတွက် ပံ့ပိုးမှုက deprecated ဖြစ်ပြီး — PostgreSQL ရဲ့ နောင် release တစ်ခုမှာ ဖယ်ရှားခံရမှာ ဖြစ်ပါတယ်။ အခြား စကားဝှက် အမျိုးအစားဆီ ပြောင်းရွှေ့ခြင်းဆိုင်ရာ အသေးစိတ်အတွက် [အပိုင်း 20.5](/docs/postgresql/auth-password) ကို ကြည့်ပါ။

- **scram_iterations (integer)** — SCRAM-SHA-256 သုံးပြီး စကားဝှက်ကို encrypt လုပ်တဲ့အခါ လုပ်ဆောင်ရမည့် တွက်ချက်မှု iteration အရေအတွက်။ ပုံမှန်က 4096။ Iteration အရေအတွက် ပိုများခြင်းက သိမ်းဆည်းထားတဲ့ စကားဝှက်များအပေါ် brute-force တိုက်ခိုက်မှုများကို အပို အကာအကွယ် ပေးပေမယ့် — authentication ကို ပိုနှေးစေပါတယ်။ Iteration အရေအတွက်က encrypt လုပ်တဲ့အချိန်မှာ ပုံသေ သတ်မှတ်ထားတာကြောင့် — တန်ဖိုး ပြောင်းလဲခြင်းက SCRAM-SHA-256 နဲ့ encrypt လုပ်ထားတဲ့ ရှိပြီးသား စကားဝှက်များအပေါ် အကျိုးသက်ရောက်မှု မရှိပါဘူး။ ပြောင်းလဲထားတဲ့ တန်ဖိုးကို အသုံးချနိုင်ရန် စကားဝှက် အသစ် သတ်မှတ်ရပါမယ်။

> **မှတ်ချက်:** postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာ သတ်မှတ်ထားတဲ့ scram_iterations တန်ဖိုးနဲ့ မတူတဲ့ iteration အရေအတွက်နဲ့ role စကားဝှက်ကို ဖန်တီးခဲ့ရင် — authentication မဖြတ်သွားတဲ့ user တစ်ဦးက ချိတ်ဆက်ရန် ကြိုးစားမှုများအပေါ် server ရဲ့ တုံ့ပြန်မှုများထဲက ကွာခြားချက်များကို လေ့လာခြင်းအားဖြင့် role ရှိနေကြောင်း ခွဲခြားသိရှိနိုင်ပါတယ်။ ဒါက သင့်အတွက် စိုးရိမ်စရာ ဖြစ်ရင် — role စကားဝှက် အားလုံးကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာ သတ်မှတ်ထားတဲ့ တန်ဖိုးနဲ့ scram_iterations သတ်မှတ်ပြီး ဖန်တီးထားကြောင်း သေချာပါစေ။

- **md5_password_warnings (boolean)** — CREATE ROLE ဒါမှမဟုတ် ALTER ROLE statement က MD5-encrypted စကားဝှက် သတ်မှတ်တဲ့အခါ MD5 စကားဝှက် deprecation အကြောင်း WARNING ထုတ်မထုတ် ထိန်းချုပ်ပါတယ်။ ပုံမှန် တန်ဖိုးက on ဖြစ်ပါတယ်။
- **krb_server_keyfile (string)** — Server ရဲ့ Kerberos key file တည်နေရာကို သတ်မှတ်ပါတယ်။ ပုံမှန်က FILE:/usr/local/pgsql/etc/krb5.keytab ဖြစ်ပါတယ် (directory အပိုင်းက build ချိန်မှာ sysconfdir အဖြစ် သတ်မှတ်ခဲ့တာ ဖြစ်သည်; ဒါကို သိရန် pg_config --sysconfdir ကို သုံးပါ)။ ဒီ parameter ကို ဗလာ string သတ်မှတ်ရင် လျစ်လျူရှုပြီး system-dependent default ကို သုံးပါတယ်။ ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။ အသေးစိတ်အတွက် [အပိုင်း 20.6](/docs/postgresql/gssapi-auth) ကို ကြည့်ပါ။
- **krb_caseins_users (boolean)** — GSSAPI user name များကို case-insensitive အနေနဲ့ သဘောထားမထား သတ်မှတ်ပါတယ်။ ပုံမှန်က off (case sensitive) ဖြစ်ပါတယ်။ ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။
- **gss_accept_delegation (boolean)** — Client ထံမှ GSSAPI delegation ကို လက်ခံမလား သတ်မှတ်ပါတယ်။ ပုံမှန်က off ဖြစ်ပြီး — ဆိုလိုတာက client ထံမှ credential များကို လက်ခံမှာ မဟုတ်ပါဘူး။ ဒါကို on ပြောင်းခြင်းက server က client ထံမှ သူ့ဆီ delegate လုပ်ထားတဲ့ credential များကို လက်ခံစေပါလိမ့်မယ်။ ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။
- **oauth_validator_libraries (string)** — OAuth connection token များ စစ်ဆေး အတည်ပြုရန် သုံးမည့် library/libraries။ Validator library တစ်ခုသာ ပေးထားရင် OAuth ချိတ်ဆက်မှု အားလုံးအတွက် ပုံမှန်အားဖြင့် ဒါကို သုံးပါလိမ့်မယ်; မဟုတ်ရင် [oauth HBA entries](/docs/postgresql/auth-oauth) အားလုံးက ဒီစာရင်းထဲမှ ရွေးချယ်ထားတဲ့ validator တစ်ခုကို အတိအကျ သတ်မှတ်ရပါမယ်။ ဗလာ string (ပုံမှန်) သတ်မှတ်ရင် OAuth ချိတ်ဆက်မှုများကို ငြင်းပါလိမ့်မယ်။ ဒီ parameter ကို postgresql.conf file မှာသာ သတ်မှတ်နိုင်ပါတယ်။
  Validator module များကို သီးခြား implement လုပ်ရ ဒါမှမဟုတ် ရယူရပါမယ်; PostgreSQL က ပုံမှန် implementation တစ်ခုမှ ပါဝင် မပေးပါဘူး။ OAuth validator များ implement လုပ်ခြင်းဆိုင်ရာ အသေးစိတ်အတွက် [အခန်း 50](https://www.postgresql.org/docs/current/oauth-validators.html) ကို ကြည့်ပါ။

### 19.3.4. SSL (SSL/TLS)

SSL စီစဉ်ခြင်းဆိုင်ရာ အသေးစိတ်အတွက် [အပိုင်း 18.9](/docs/postgresql/ssl-tcp) ကို ကြည့်ပါ။ TLS protocol များ သုံးပြီး transfer encryption ကို ထိန်းချုပ်တဲ့ configuration parameter များကို — SSL protocol အတွက် ပံ့ပိုးမှုက deprecated ဖြစ်နေပေမယ့် — သမိုင်းဝင် အကြောင်းပြချက်ဖြင့် `ssl` လို့ အမည်ပေးထားပါတယ်။ ဒီအခင်းအကျင်းမှာ SSL ကို TLS နဲ့ အဓိပ္ပာယ် တူညီစွာ သုံးပါတယ်။

- **ssl (boolean)** — SSL ချိတ်ဆက်မှုများကို ဖွင့်ပေးပါတယ်။ ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။ ပုံမှန်က off ဖြစ်ပါတယ်။
- **ssl_ca_file (string)** — SSL server certificate authority (CA) ပါဝင်တဲ့ file အမည်ကို သတ်မှတ်ပါတယ်။ Relative path များက data directory ကို အခြေခံပါတယ်။ ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။ ပုံမှန်က ဗလာ ဖြစ်ပြီး — ဆိုလိုတာက CA file မည်တစ်ခုမှ load မလုပ်ဘဲ client certificate စစ်ဆေးအတည်ပြုခြင်းကို မလုပ်တာပါ။
- **ssl_cert_file (string)** — SSL server certificate ပါဝင်တဲ့ file အမည်ကို သတ်မှတ်ပါတယ်။ Relative path များက data directory ကို အခြေခံပါတယ်။ ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။ ပုံမှန်က server.crt ဖြစ်ပါတယ်။
- **ssl_crl_file (string)** — SSL client certificate revocation list (CRL) ပါဝင်တဲ့ file အမည်ကို သတ်မှတ်ပါတယ်။ Relative path များက data directory ကို အခြေခံပါတယ်။ ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။ ပုံမှန်က ဗလာ ဖြစ်ပြီး — ဆိုလိုတာက (ssl_crl_dir သတ်မှတ်မထားရင်) CRL file မည်တစ်ခုမှ load မလုပ်တာပါ။
- **ssl_crl_dir (string)** — SSL client certificate revocation list (CRL) ပါဝင်တဲ့ directory အမည်ကို သတ်မှတ်ပါတယ်။ Relative path များက data directory ကို အခြေခံပါတယ်။ ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။ ပုံမှန်က ဗလာ ဖြစ်ပြီး — ဆိုလိုတာက (ssl_crl_file သတ်မှတ်မထားရင်) CRL များကို သုံးမှာ မဟုတ်တာပါ။
  Directory ကို OpenSSL command openssl rehash ဒါမှမဟုတ် c_rehash နဲ့ ပြင်ဆင်ထားရန် လိုအပ်ပါတယ်။ အသေးစိတ်အတွက် သူ့ documentation ကို ကြည့်ပါ။
  ဒီ setting ကို သုံးတဲ့အခါ သတ်မှတ်ထားတဲ့ directory ထဲက CRL များကို ချိတ်ဆက်ချိန်မှာ on-demand အနေနဲ့ load ပါတယ်။ CRL အသစ်များကို directory ထဲ ထည့်နိုင်ပြီး — ချက်ချင်း အသုံးပြုပါလိမ့်မယ်။ ဒါက — file ထဲက CRL ကို server စတင်ချိန် ဒါမှမဟုတ် configuration ပြန်လည် load လုပ်ချိန်မှာ load စေတဲ့ — ssl_crl_file နဲ့ မတူပါဘူး။ setting နှစ်ခုလုံးကို အတူတကွ သုံးနိုင်ပါတယ်။
- **ssl_key_file (string)** — SSL server private key ပါဝင်တဲ့ file အမည်ကို သတ်မှတ်ပါတယ်။ Relative path များက data directory ကို အခြေခံပါတယ်။ ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။ ပုံမှန်က server.key ဖြစ်ပါတယ်။
- **ssl_tls13_ciphers (string)** — TLS version 1.3 သုံးတဲ့ ချိတ်ဆက်မှုများက ခွင့်ပြုတဲ့ cipher suite များရဲ့ စာရင်းကို သတ်မှတ်ပါတယ်။ Colon နဲ့ ခွဲထားတဲ့ စာရင်းကို သုံးပြီး cipher suite များစွာ သတ်မှတ်နိုင်ပါတယ်။ ဗလာထားရင် OpenSSL ထဲက ပုံမှန် cipher suite အစုကို သုံးပါလိမ့်မယ်။
  ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။
- **ssl_ciphers (string)** — TLS version 1.2 နဲ့ အောက် သုံးတဲ့ ချိတ်ဆက်မှုများက ခွင့်ပြုတဲ့ SSL cipher များရဲ့ စာရင်းကို သတ်မှတ်ပါတယ် — TLS version 1.3 ချိတ်ဆက်မှုများအတွက် ssl_tls13_ciphers ကို ကြည့်ပါ။ ဒီ setting ရဲ့ syntax နဲ့ ပံ့ပိုးထားတဲ့ တန်ဖိုး စာရင်းအတွက် OpenSSL package ထဲက ciphers manual page ကို ကြည့်ပါ။ ပုံမှန် တန်ဖိုးက HIGH:MEDIUM:+3DES:!aNULL ဖြစ်ပါတယ်။ သီးခြား လုံခြုံရေး လိုအပ်ချက်များ မရှိရင် ပုံမှန်တန်ဖိုးသည် များသောအားဖြင့် သင့်တင့်တဲ့ ရွေးချယ်မှု ဖြစ်ပါတယ်။
  ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။
  ပုံမှန်တန်ဖိုး ရှင်းလင်းချက်:

`HIGH`

HIGH group ထဲက cipher များ (ဥပမာ — AES, Camellia, 3DES) သုံးတဲ့ cipher suite များ

`MEDIUM`

MEDIUM group ထဲက cipher များ (ဥပမာ — RC4, SEED) သုံးတဲ့ cipher suite များ

`+3DES`

HIGH အတွက် OpenSSL ပုံမှန် အစီအစဉ်က 3DES ကို AES128 ထက် ပိုမြင့်တဲ့ အစီအစဉ်မှာ ထားတာကြောင့် ပြဿနာရှိပါတယ်။ ဒါက 3DES က AES128 ထက် လုံခြုံမှု နည်းပြီး — ပိုလည်း နှေးတာကြောင့် မှားပါတယ်။ +3DES က ဒါကို အခြား HIGH နဲ့ MEDIUM cipher အားလုံးရဲ့ နောက်မှ ပြန်စီပါတယ်။

`!aNULL`

Authentication လုံးဝ မလုပ်တဲ့ anonymous cipher suite များကို ပိတ်ပါတယ်။ ဒီလို cipher suite များက MITM တိုက်ခိုက်မှုများကို ခံနိုင်ရည် မရှိတာကြောင့် မသုံးသင့်ပါဘူး။

ရရှိနိုင်တဲ့ cipher suite အသေးစိတ်များက OpenSSL version များအလိုက် ကွဲပြားပါလိမ့်မယ်။ လက်ရှိ install လုပ်ထားတဲ့ OpenSSL version အတွက် အမှန်တကယ် အသေးစိတ်ကို ကြည့်ရန် openssl ciphers -v 'HIGH:MEDIUM:+3DES:!aNULL' command ကို သုံးပါ။ ဒီစာရင်းကို run time မှာ server key type ပေါ် အခြေခံပြီး filter လုပ်တယ်ဆိုတာ သတိပြုပါ။
- **ssl_prefer_server_ciphers (boolean)** — Client ရဲ့ ရွေးချယ်မှုများအစား server ရဲ့ SSL cipher ရွေးချယ်မှုများကို သုံးမလား သတ်မှတ်ပါတယ်။ ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။ ပုံမှန်က on ဖြစ်ပါတယ်။
  PostgreSQL 9.4 မတိုင်မီ version များမှာ ဒီ setting မရှိဘဲ client ရဲ့ ရွေးချယ်မှုများကို အမြဲ သုံးပါတယ်။ ဒီ setting က အဓိကအားဖြင့် အဲဒီ version များနဲ့ နောက်ပြန် ကိုက်ညီမှု (backward compatibility) အတွက် ဖြစ်ပါတယ်။ Server ရဲ့ ရွေးချယ်မှုများ သုံးခြင်းက များသောအားဖြင့် ပိုကောင်းပါတယ် — အကြောင်းကတော့ server က သင့်လျော်စွာ configure လုပ်ထားနိုင်ခြေ ပိုများလို့ပါ။
- **ssl_groups (string)** — TLS key exchange အတွက် သုံးမည့် named group ကို သတ်မှတ်ပါတယ်။ ဒါကို ချိတ်ဆက်တဲ့ client အားလုံး ပံ့ပိုးရပါမယ်။ Group များစွာကို colon နဲ့ ခွဲထားတဲ့ စာရင်းနဲ့ သတ်မှတ်နိုင်ပါတယ်။ Server certificate သုံးတဲ့ key type နဲ့ တူညီရန် မလိုအပ်ပါဘူး။ ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။ ပုံမှန်က X25519:prime256v1 ဖြစ်ပါတယ်။
  အသုံးအများဆုံး group များအတွက် OpenSSL အမည်များက — prime256v1 (NIST P-256), secp384r1 (NIST P-384), secp521r1 (NIST P-521) ဖြစ်ပါတယ်။ ရရှိနိုင်တဲ့ group များရဲ့ မပြည့်စုံတဲ့ စာရင်းကို openssl ecparam -list_curves command နဲ့ ပြနိုင်ပါတယ်။ ဒါပေမယ့် အားလုံးက TLS နဲ့ သုံးလို့ မရဘူးဆိုတာ သတိပြုပါ — ပံ့ပိုးထားတဲ့ group အမည်နဲ့ alias အများအပြားကို ချန်လှပ်ထားပါတယ်။
  PostgreSQL 18.0 မတိုင်မီ version များမှာ ဒီ setting ကို ssl_ecdh_curve လို့ အမည်ပေးထားပြီး တန်ဖိုး တစ်ခုတည်းကိုသာ လက်ခံပါတယ်။
- **ssl_min_protocol_version (enum)** — သုံးမည့် အနိမ့်ဆုံး SSL/TLS protocol version ကို သတ်မှတ်ပါတယ်။ လက်ရှိ ဖြစ်နိုင်တဲ့ တန်ဖိုးများက — TLSv1, TLSv1.1, TLSv1.2, TLSv1.3 ဖြစ်ပါတယ်။ OpenSSL library version အဟောင်းများက တန်ဖိုး အားလုံးကို ပံ့ပိုးမထားပါဘူး; ပံ့ပိုးမထားတဲ့ setting ကို ရွေးချယ်ရင် error တစ်ခု ဖြစ်ပေါ်ပါလိမ့်မယ်။ TLS 1.0 မတိုင်မီ protocol version များ — ဆိုလိုတာက SSL version 2 နဲ့ 3 — ကို အမြဲတမ်း ပိတ်ထားပါတယ်။
  ပုံမှန်က TLSv1.2 ဖြစ်ပြီး — ဒီစာရေးချိန်အထိ စက်မှုလုပ်ငန်း အကောင်းဆုံး ကျင့်သုံးမှုများနဲ့ ကိုက်ညီပါတယ်။
  ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။
- **ssl_max_protocol_version (enum)** — သုံးမည့် အမြင့်ဆုံး SSL/TLS protocol version ကို သတ်မှတ်ပါတယ်။ ဖြစ်နိုင်တဲ့ တန်ဖိုးများက ssl_min_protocol_version အတွက်ကဲ့သို့ပဲ ဖြစ်ပြီး — protocol version မည်သည်ကိုမဆို ခွင့်ပြုတဲ့ ဗလာ string ကိုပါ ထပ်တိုးထားပါတယ်။ ပုံမှန်က version မည်သည်ကိုမဆို ခွင့်ပြုတာပါ။ အမြင့်ဆုံး protocol version သတ်မှတ်ခြင်းက အဓိကအားဖြင့် စမ်းသပ်ရန် ဒါမှမဟုတ် အချို့ component တစ်ခုက protocol အသစ်နဲ့ အလုပ်လုပ်ရာမှာ ပြဿနာရှိရင် အသုံးဝင်ပါတယ်။
  ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။
- **ssl_dh_params_file (string)** — so-called ephemeral DH မျိုးရင်း SSL cipher များအတွက် သုံးတဲ့ Diffie-Hellman parameter များ ပါဝင်တဲ့ file အမည်ကို သတ်မှတ်ပါတယ်။ ပုံမှန်က ဗလာ ဖြစ်ပြီး — အဲဒီအခါ compile ထဲ ပါဝင်တဲ့ ပုံမှန် DH parameter များကို သုံးပါတယ်။ စိတ်ကြိုက် DH parameter များ သုံးခြင်းက — တိုက်ခိုက်သူတစ်ဦးက လူသိများတဲ့ compile ထဲပါ DH parameter များကို ဖောက်ထွင်းနိုင်ခဲ့ရင် — ထိတွေ့နိုင်မှုကို လျှော့ချပေးပါတယ်။ openssl dhparam -out dhparams.pem 2048 command နဲ့ သင့်ကိုယ်ပိုင် DH parameter file ကို ဖန်တီးနိုင်ပါတယ်။
  ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။
- **ssl_passphrase_command (string)** — Private key ကဲ့သို့ SSL file တစ်ခုကို decrypt လုပ်ဖို့ passphrase ရယူရန် လိုအပ်တဲ့အခါ ခေါ်ယူမည့် external command ကို သတ်မှတ်ပါတယ်။ ပုံမှန်အားဖြင့် ဒီ parameter က ဗလာ ဖြစ်ပြီး — ဆိုလိုတာက built-in prompting ယန္တရားကို သုံးတာပါ။
  Command က passphrase ကို standard output ဆီ print လုပ်ပြီး ကုဒ် 0 နဲ့ ထွက်ရပါမယ်။ Parameter တန်ဖိုးထဲမှာ %p ကို prompt string တစ်ခုနဲ့ အစားထိုးပါတယ်။ (literal % အတွက် %% လို့ ရေးပါ။) Prompt string မှာ whitespace ပါနိုင်ခြေ များတာကြောင့် — လုံလောက်အောင် quote လုပ်ပါ။ Output အဆုံးမှာ newline တစ်ခု ရှိရင် ဖယ်ရှားပါတယ်။
  Command က user ကို passphrase အတွက် တကယ် prompt လုပ်ရန် မလိုအပ်ပါဘူး။ ဒါကို file တစ်ခုကနေ ဖတ်နိုင်၊ keychain facility တစ်ခုကနေ ရယူနိုင်စသဖြင့် လုပ်နိုင်ပါတယ်။ ရွေးချယ်ထားတဲ့ ယန္တရားက လုံလောက်စွာ လုံခြုံကြောင်း သေချာစေဖို့က user အပေါ် မူတည်ပါတယ်။
  ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။
- **ssl_passphrase_command_supports_reload (boolean)** — Key file တစ်ခုက passphrase လိုအပ်ရင် — ssl_passphrase_command က သတ်မှတ်ထားတဲ့ passphrase command ကို configuration reload လုပ်ချိန်မှာလည်း ခေါ်မလား ဒီ parameter က ဆုံးဖြတ်ပါတယ်။ ဒီ parameter က off (ပုံမှန်) ဖြစ်ရင် — reload လုပ်ချိန်မှာ ssl_passphrase_command ကို လျစ်လျူရှုပြီး — passphrase လိုအပ်ရင် SSL configuration ကို ပြန်လည် load လုပ်မှာ မဟုတ်ပါဘူး။ အဲဒီ setting က prompting အတွက် TTY လိုအပ်တဲ့ command များအတွက် သင့်တင့်ပြီး — server run နေချိန်မှာ TTY မရရှိနိုင်ပါဘူး။ ဥပမာ passphrase ကို file ကနေ ရယူရင် ဒီ parameter ကို on သတ်မှတ်ခြင်းက သင့်တင့်နိုင်ပါတယ်။
  Windows ပေါ်မှာ run ရင် ဒီ parameter ကို on သတ်မှတ်ရပါမယ် — အကြောင်းကတော့ အဲဒီ platform ရဲ့ မတူညီတဲ့ process model ကြောင့် ချိတ်ဆက်မှု အားလုံးက configuration reload ကို လုပ်ဆောင်မှာ ဖြစ်လို့ပါ။
  ဒီ parameter ကို postgresql.conf file မှာ ဒါမှမဟုတ် server command line မှာသာ သတ်မှတ်နိုင်ပါတယ်။
